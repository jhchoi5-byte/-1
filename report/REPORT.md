# 정렬 알고리즘의 입력 특성 및 크기에 따른 성능 비교

*— Shell Sort, Merge Sort, Library Sort를 중심으로*

## 1. 서론

### 1.1 과제 목적

정렬 알고리즘은 동일한 정렬 결과를 생성하더라도 알고리즘의 구조와 입력 데이터의 특성에 따라 실행 시간과 필요한 추가 메모리가 달라질 수 있다. 따라서 알고리즘을 단순히 이론적인 시간 복잡도만으로 비교하기보다는 실제 구현을 통해 다양한 입력 조건에서 성능을 측정하고 그 결과를 이론적 특성과 함께 분석할 필요가 있다.
본 과제에서는 Shell Sort, Merge Sort, Library Sort의 세 가지 정렬 알고리즘을 직접 구현하고 동일한 조건에서 실행 시간을 측정하였다. 특히 입력 데이터의 크기뿐만 아니라 배열의 초기 상태가 성능에 미치는 영향을 확인하기 위해 무작위 배열(random), 이미 정렬된 배열(already sorted), 역순 배열(reverse sorted), 중복 값이 많은 배열(duplicate heavy)의 네 가지 입력 형태를 사용하였다.
또한 수업에서 직접 다루지 않은 Library Sort를 AI를 활용하여 학습하고 구현함으로써, AI를 단순한 코드 생성 도구가 아니라 새로운 알고리즘의 원리와 구현 방법을 학습하는 보조 도구로 활용하고자 하였다.
### 1.2 비교 알고리즘 선정

본 과제에서 비교한 알고리즘은 Shell Sort, Merge Sort, Library Sort이다.
Shell Sort는 일정한 간격(gap)을 기준으로 떨어진 원소들을 비교·정렬하고 점차 gap을 줄이는 방식이며, 비교적 적은 추가 메모리를 사용한다. Merge Sort는 배열을 반복적으로 분할한 뒤 정렬된 부분 배열을 병합하는 divide-and-conquer 방식의 대표적인 정렬 알고리즘이다.
Library Sort는 정렬된 원소 사이에 의도적으로 빈 공간(gap)을 유지하고 새로운 원소를 해당 공간에 삽입하는 아이디어를 사용하는 알고리즘이다. 본 과제에서는 AI를 이용하여 Library Sort의 원리를 학습한 후 deterministic educational variant를 구현하였다.
### 1.3 알고리즘 선정 이유

세 알고리즘은 정렬을 수행하는 방식이 서로 크게 다르다는 점에서 비교 대상으로 선정하였다. Shell Sort는 gap을 이용한 삽입 기반 방식이고, Merge Sort는 분할 및 병합 방식이며, Library Sort는 추가 공간에 빈 슬롯을 유지하면서 삽입하는 방식이다.
따라서 동일한 입력을 세 알고리즘에 적용하면 알고리즘의 구조적 차이가 실제 실행 시간에 어떤 영향을 주는지 비교할 수 있다고 판단하였다. 특히 Library Sort는 기존에 학습하지 않았던 알고리즘이므로 AI를 이용한 새로운 알고리즘 학습이라는 과제의 목적에도 적합하였다.

## 2. 알고리즘 구현 및 검증

### 2.1 구현 환경

본 과제의 알고리즘 및 성능 측정은 GitHub Codespaces 환경에서 진행하였다. 성능 비교의 주 실험은 C로 구현된 정렬 알고리즘을 이용하였다.
세 알고리즘은 동일한 형태의 인터페이스를 사용하도록 구성하였다.
```c
void sortName(int a[], int n);
```
이를 통해 동일한 입력 배열에 서로 다른 정렬 함수를 적용할 수 있도록 하였으며, benchmark 과정에서도 동일한 조건으로 각 알고리즘을 호출할 수 있도록 하였다.
### 2.2 Shell Sort 구현

Shell Sort는 일정한 간격을 두고 원소를 비교한 뒤 gap을 점차 감소시키는 방식으로 구현하였다. 본 구현에서는 배열 크기의 절반에서 시작하여 gap을 반복적으로 감소시키는 방법을 사용하였다.
각 gap 단계에서는 해당 간격만큼 떨어진 원소들을 대상으로 insertion-sort와 유사한 방식의 이동을 수행한다. 마지막으로 gap이 1이 되면 일반적인 삽입 정렬과 유사한 형태로 전체 배열이 정렬된다.
Shell Sort는 별도의 대규모 보조 배열을 필요로 하지 않는다는 장점이 있다.
### 2.3 Merge Sort 구현

Merge Sort는 배열을 재귀적으로 두 부분으로 나누고 각각을 정렬한 뒤 두 정렬된 배열을 다시 하나로 병합하는 방식으로 구현하였다.
분할 과정은 배열의 크기가 충분히 작아질 때까지 반복되며, 병합 과정에서는 두 부분 배열의 현재 원소를 비교하면서 작은 값을 결과 배열에 순차적으로 배치한다.
Shell Sort와 달리 병합을 수행하기 위한 추가 메모리가 필요하지만, 입력 배열의 초기 순서와 관계없이 구조적으로 분할과 병합 과정을 수행한다.
### 2.4 Library Sort 구현

Library Sort는 AI를 이용해 알고리즘의 기본 원리와 구현 시 고려해야 할 요소를 먼저 학습한 후 구현하였다.
본 구현에서는 정렬된 원소 사이에 빈 슬롯을 유지하기 위해 원래 배열보다 큰 내부 저장 공간을 사용하였다. 빈 슬롯은 특정 정수값을 sentinel로 사용하는 대신 별도의 occupancy 정보를 이용하여 구분하였다. 이를 통해 음수나 매우 큰 정수 등 특정 값을 빈 공간 표시용으로 사용할 때 발생할 수 있는 문제를 방지하였다.
새로운 원소를 삽입할 위치를 탐색한 후 가까운 빈 슬롯을 이용하여 원소를 이동시키고, 빈 공간의 분포가 적절하지 않을 경우 기존 원소를 다시 분산시키는 rebalance 과정을 수행하도록 구현하였다.
다만 본 과제에서 구현한 Library Sort는 이론적 분석에서 사용되는 모든 randomized Library Sort를 그대로 구현한 것이 아니라, 학습과 비교 실험을 목적으로 구현한 결정적 교육용 변형이다. 따라서 이후 실험 결과 역시 해당 구현에 한정하여 해석하였다.
### 2.5 구현 검증

정렬 알고리즘의 정확성을 확인하기 위해 다양한 입력에 대한 테스트를 수행하였다. 혼합된 배열뿐만 아니라 이미 정렬된 배열, 역순 배열, 중복값을 포함한 배열, 원소가 하나인 배열 및 빈 배열 등을 테스트하였다.
최종적으로 기존 테스트에서 C의 24개 검증 항목과 Python의 6개 테스트가 모두 통과하였다. 또한 Library Sort 구현 과정에서는 별도의 독립적인 입력 검증도 수행하여 다양한 배열 크기와 중복값을 포함하는 경우에 정렬 결과가 기대 결과와 일치하는지 확인하였다.
성능 실험에서도 각 정렬 결과를 독립적으로 생성한 정답 배열과 비교하였으며, 최종 2,160회의 측정 결과가 모두 정확한 정렬 결과를 생성하였다.

## 3. 알고리즘의 이론적 특성

### 3.1 Shell Sort

Shell Sort는 서로 멀리 떨어져 있는 원소들을 먼저 정렬한 뒤 비교 간격을 점차 줄이는 방식이다. 일반적인 insertion sort에서는 멀리 떨어진 위치로 원소를 이동시키기 위해 많은 이동이 필요할 수 있지만, Shell Sort는 큰 gap을 이용하여 원소를 먼저 대략적인 위치로 이동시킨다.
Shell Sort의 시간 복잡도는 사용하는 gap sequence에 크게 영향을 받는다. 따라서 Shell Sort 전체를 하나의 고정된 시간 복잡도로 표현하는 데에는 주의가 필요하다. 본 구현에서 사용한 gap 방식 역시 해당 구현을 기준으로 성능을 해석해야 한다.
추가적인 대규모 배열을 필요로 하지 않으므로 공간 사용량이 작으며, 일반적으로 안정 정렬은 아니다.
### 3.2 Merge Sort

Merge Sort는 divide-and-conquer 원리를 이용한다. 배열을 절반으로 분할하고 각각을 정렬한 뒤 두 정렬된 부분 배열을 하나로 병합한다.
배열을 약 `log n` 단계로 분할하고 각 단계에서 전체 원소에 해당하는 병합 작업을 수행하기 때문에 일반적으로 시간 복잡도는 `O(n log n)`이다.
반면 병합을 위한 추가 저장 공간이 필요하기 때문에 배열 기반 구현에서는 일반적으로 `O(n)`의 추가 공간이 필요하다. 본 구현에서는 동일한 값을 병합할 때 왼쪽 원소를 우선 선택하도록 구현되어 안정성이 유지된다.
### 3.3 Library Sort

Library Sort의 핵심 아이디어는 도서관의 책장에 책을 배치할 때 새로운 책을 쉽게 삽입하기 위해 책 사이에 여유 공간을 남겨 두는 것과 유사하다.
일반적인 배열 기반 insertion 과정에서는 삽입 위치 뒤의 많은 원소를 이동시켜야 할 수 있다. Library Sort는 원소 사이에 빈 공간을 유지함으로써 이러한 이동 비용을 줄이는 것을 목표로 한다. 빈 공간이 부족하거나 한쪽에 집중될 경우에는 원소를 다시 분산시키는 rebalance가 필요하다.
특정 randomized Library Sort에서는 적절한 가정 아래 기대 `O(n log n)` 성능이 논의되지만, 이러한 성질을 모든 Library Sort 구현에 그대로 적용할 수는 없다. 특히 본 과제에서 구현한 deterministic educational variant는 특정 입력에서 많은 이동과 재배치가 발생할 수 있으며 최악의 경우에는 상당히 큰 비용이 발생할 수 있다.
또한 빈 슬롯을 유지하기 위한 추가 저장 공간이 필요하므로 `O(n)` 규모의 추가 공간을 사용한다. 안정성은 구체적인 구현 방법에 의존하므로 Library Sort 자체를 항상 안정 정렬이라고 할 수 없다.
### 3.4 세 알고리즘 비교

| 특성 | Shell Sort | Merge Sort | Library Sort* |
| --- | --- | --- | --- |
| 핵심 원리 | Gap 기반 삽입 | 분할 후 병합 | 빈 슬롯을 이용한 삽입 |
| 추가 공간 | 작음 | `O(n)` | `O(n)` |
| 입력 순서 영향 | 있음 | 상대적으로 작음 | 구현에 따라 큼 |
| 안정성 | 일반적으로 불안정 | 본 구현은 안정 | 구현 의존 |
| 특징 | 구현이 단순하고 추가 메모리가 적음 | 예측 가능한 정렬 구조 | Gap과 rebalance 이용 |
* Library Sort는 본 과제에서 사용한 deterministic educational variant를 중심으로 설명하였다.

## 4. AI를 활용한 Library Sort 학습 및 구현

### 4.1 학습 목적

Library Sort는 기존에 알고 있던 정렬 알고리즘이 아니었기 때문에 구현에 앞서 AI를 이용하여 알고리즘의 기본적인 원리와 기존 정렬 알고리즘과의 차이를 학습하였다.
단순히 완성된 코드를 생성하도록 요청하기보다 먼저 알고리즘이 어떤 아이디어를 이용하고 왜 빈 공간을 사용하는지 이해하는 과정을 거쳤다.
### 4.2 AI에게 질문한 내용

AI에게 우선 Library Sort의 기본 원리, gap의 역할, 새로운 원소의 삽입 방법, 빈 공간이 부족할 때 수행하는 rebalance 과정 등에 대해 질문하였다.
또한 시간 및 공간 복잡도, 안정성 여부, Shell Sort 및 Merge Sort와의 차이를 질문하였다.
구현 단계에서는 C의 `int[]` 배열에서 빈 공간을 안전하게 표현하는 방법, 추가 배열의 구성, 검색 및 원소 이동 방법, rebalance 구현 방법 등을 추가로 질문하였다.
### 4.3 AI를 통해 학습한 내용

AI와의 질의 과정에서 단순히 빈 공간을 둔다고 해서 항상 적은 원소 이동이 보장되는 것은 아니라는 점을 알게 되었다. 가까운 위치에 적절한 빈 슬롯이 존재하지 않는다면 빈 공간을 찾기 위해 추가적인 탐색이나 이동이 필요할 수 있다.
또한 문헌에서 설명되는 Library Sort의 기대 시간 복잡도가 모든 구현에 자동으로 적용되는 것이 아니라는 점도 중요하게 확인하였다. 특히 randomized 방식과 본 과제에서 구현한 deterministic 방식은 구분하여 해석할 필요가 있었다.
이를 바탕으로 특정 정수값을 빈 공간을 의미하는 sentinel로 사용하는 대신 occupancy 정보를 별도로 저장하고, 일정한 조건에서 원소를 다시 분산시키는 방식으로 구현하였다.
### 4.4 AI 활용에 대한 평가

AI는 처음 접하는 알고리즘의 개념을 빠르게 파악하고 구현 시 발생할 수 있는 문제를 찾는 데 유용하였다. 특히 알고리즘의 이론적 특성과 실제 구현의 특성을 구분하는 데 도움을 받을 수 있었다.
반면 AI의 설명이나 생성된 구현을 그대로 받아들이는 것만으로 정확성을 보장할 수는 없었다. 따라서 테스트 케이스와 독립적인 정답 비교를 통해 구현 결과를 별도로 검증하였다.

## 5. 실험 방법

### 5.1 실험 환경

성능 실험은 GitHub Codespaces 환경에서 C로 구현된 세 정렬 알고리즘을 대상으로 수행하였다. 모든 알고리즘은 동일한 실행 환경과 benchmark 프로그램에서 측정하였다.
### 5.2 입력 데이터

알고리즘의 성능이 입력 배열의 초기 상태에 따라 어떻게 변화하는지 확인하기 위해 네 가지 입력 형태를 사용하였다.
- Random: 무작위 순열
- Already sorted: 오름차순으로 정렬된 배열
- Reverse sorted: 내림차순으로 정렬된 배열
- Duplicate heavy: 제한된 범위의 값이 반복적으로 나타나는 배열

각 trial에서는 하나의 원본 입력을 생성한 뒤 동일한 입력을 복사하여 세 알고리즘에 사용하였다. 따라서 알고리즘별 입력 차이에 의한 영향을 최소화하였다.
### 5.3 입력 크기

입력 배열의 크기는
`500, 1,000, 2,000, 5,000, 10,000, 20,000`
의 여섯 단계로 설정하였다.
이를 통해 작은 입력에서부터 비교적 큰 입력까지 배열의 크기가 증가할 때 각 알고리즘의 실행 시간이 어떻게 변화하는지 관찰하였다.
### 5.4 측정 방법

실행 시간은 monotonic clock을 이용하여 측정하였으며 nanosecond 단위의 측정값을 저장하였다.
측정 구간에는 선택된 정렬 함수의 실행만 포함하였다. 입력 생성, 배열 복사, 정답 배열 생성, 결과 검증 및 CSV 출력은 측정 구간에서 제외하였다.
단, Merge Sort 및 Library Sort가 함수 내부에서 수행하는 메모리 할당 및 해제는 실제 알고리즘 호출 과정의 일부이므로 측정 시간에 포함하였다.
각 알고리즘의 실행 결과는 별도로 생성한 정답 배열과 비교하여 정확성을 확인하였다.
### 5.5 반복 측정과 실행 순서

각 (algorithm, input size, distribution) 조건을 30회씩 반복 측정하였다.
총 측정 횟수는
`3 × 6 × 4 × 30 = 2,160회`
이다.
알고리즘이 항상 같은 순서로 실행될 경우 먼저 실행되는 알고리즘이나 나중에 실행되는 알고리즘에 시스템 상태가 영향을 줄 가능성이 있으므로 세 알고리즘의 가능한 6가지 실행 순서를 사용하였다.
30회의 trial 동안 각 실행 순서를 5회씩 사용하였으며, 결과적으로 각 알고리즘이 첫 번째, 두 번째, 세 번째 위치에서 각각 10회씩 실행되도록 구성하였다.
대표적인 실행 시간으로는 30회 측정의 median을 사용하였다. 일부 짧은 실행에서는 시스템 상태 등에 의해 긴 꼬리를 가진 측정값이 발생하여 평균이 크게 영향을 받을 수 있었기 때문이다.

## 7. 결과 분석 및 비교

### 7.1 입력 크기에 따른 성능 변화

입력 크기가 `500`에서 `20,000`으로 40배 증가했을 때 대부분의 조건에서 실행시간의 median도 증가하였다.
Random 입력에서는 Shell Sort가 약 62.0배, Merge Sort가 약 48.9배, Library Sort가 약 56.5배 증가하였다. 반면 already-sorted 입력에서 Library Sort는 약 778.8배, reverse-sorted에서는 약 1,337배 증가하였다.
이 값은 본 실험 구간에서 관찰된 실행시간 증가율이며, 이를 그대로 알고리즘의 점근적 시간 복잡도로 해석해서는 안 된다.
### 7.2 입력 데이터 형태에 따른 성능 차이

Shell Sort와 Merge Sort에서는 random 입력이 상대적으로 긴 실행시간을 보였다. `n=20,000` random 조건에서 Shell Sort는 약 1.93 ms, Merge Sort는 약 1.42 ms였다.
반면 already-sorted 조건에서는 각각 약 0.266 ms와 0.348 ms, reverse-sorted에서는 약 0.322 ms와 0.332 ms로 측정되었다.
Library Sort에서는 입력 형태에 따른 차이가 훨씬 크게 나타났다. `n=20,000`에서 random 입력은 약 5.22 ms였으나 duplicate-heavy는 약 30.48 ms, reverse-sorted는 약 321.85 ms, already-sorted는 약 411.09 ms였다.
따라서 본 과제에서 구현한 Library Sort 변형은 입력 데이터의 초기 순서에 매우 민감한 성능을 나타냈다.
### 7.3 Library Sort의 성능 분석

Library Sort가 sorted 및 reverse-sorted 입력에서 큰 실행시간을 나타낸 현상은 pilot experiment에서도 관찰되었으며, 30회의 최종 실험에서도 동일한 경향이 재현되었다.
현재 구현에서는 새로운 원소의 삽입 위치를 찾는 것뿐만 아니라 주변의 빈 슬롯을 탐색하고 필요에 따라 원소를 이동시키거나 전체적인 빈 공간을 다시 배치하는 과정이 수행된다.
따라서 입력 순서에 따라 이러한 과정의 빈도와 비용이 달라졌을 가능성이 있다. 그러나 본 benchmark에서는 gap 탐색 횟수, 이동 횟수 및 rebalance 횟수를 각각 별도로 측정하지 않았기 때문에 특정 과정이 성능 저하의 직접적인 원인이라고 단정할 수는 없다.
또한 이러한 결과는 본 과제에서 구현한 deterministic educational variant에 대한 결과이며 일반적인 Library Sort의 성능을 의미하지 않는다.
### 7.4 세 알고리즘의 특징 비교

실험 결과 Merge Sort는 random 입력에서 세 알고리즘 중 가장 짧은 median 실행시간을 나타냈다. Shell Sort는 already-sorted와 reverse-sorted 입력에서 특히 짧은 실행시간을 보였으며 추가 메모리 사용량이 작다는 장점도 있다.
Library Sort는 random 입력에서는 다른 두 알고리즘과의 차이가 상대적으로 작았지만 sorted와 reverse-sorted 입력에서는 실행시간이 크게 증가하였다.
이 결과는 알고리즘의 성능을 단순히 하나의 시간복잡도 표현만으로 판단하기 어렵다는 점을 보여준다. 동일한 알고리즘이라도 구체적인 구현 방식과 입력 데이터의 특성에 따라 실제 실행시간이 크게 달라질 수 있다.

## 8. 결론

본 과제에서는 Shell Sort, Merge Sort, Library Sort를 구현하고 네 가지 입력 형태와 여섯 가지 입력 크기를 대상으로 총 2,160회의 실행시간 측정을 수행하였다.
실험 결과 Merge Sort는 random 입력에서 안정적으로 짧은 실행시간을 보였으며, Shell Sort는 이미 정렬되거나 역순으로 정렬된 입력에서 매우 짧은 실행시간을 나타냈다. 반면 본 과제에서 구현한 Library Sort는 random 입력에서는 상대적으로 작은 실행시간을 보였지만 sorted와 reverse-sorted 입력에서는 입력 크기가 증가함에 따라 실행시간이 크게 증가하였다.
이러한 결과를 통해 이론적 시간 복잡도는 알고리즘의 성능을 이해하는 중요한 기준이지만, 실제 성능은 입력 데이터의 형태, 구체적인 구현 방식, 추가 메모리 관리 및 실행 환경에도 영향을 받을 수 있음을 확인하였다.
또한 AI를 활용하여 처음 접하는 Library Sort의 개념을 학습하고 실제 구현으로 연결하는 과정을 경험하였다. 이 과정에서 AI가 알고리즘 학습과 구현을 지원하는 데 유용하지만, AI가 제공한 설명이나 코드를 그대로 받아들이기보다는 테스트와 실험을 통해 결과를 독립적으로 검증하는 과정이 필요하다는 점도 확인하였다.
